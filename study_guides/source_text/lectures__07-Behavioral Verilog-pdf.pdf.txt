                Behavioral Verilog
Behavioral Verilog
• Structural: connect existing blocks
• Dataflow: specify exactly how each bit is manipulated
• Behavioral: describe what the hardware should do as a procedure

• Goal: abstract away the details of the hardware implementation to
  make design easier

• The synthesizer creates a hardware structures that does the same thing
  as your description
  • … but the synthesizer has to be able to realize your description using real hardware constraints
  • This is why not all Verilog constructs are supported
  • You still need to “think hardware” then describe it using Verilog
Behavioral Verilog
• All behavioral statements occur in procedural blocks: initial, always
  • Statements are evaluated top to bottom (look a lot like C code)
  • All <LHS> assignments must be to type reg or logic
  • initial and always blocks cannot be nested
  • Can have multiple blocks, all evaluate concurrently

• initial statements start at time 0 and execute once
  • Multiple initial blocks will all start at time 0 and execute independently
  • Not synthesizable, use only in testbench
    • If you are tempted to use initial blocks in your design, it means you are not resetting the flops
      you need to reset
• always statements will evaluate continuously
  • Synthesizable

always Statements
• Operates continuously (always)
 • Executes at time 0, but loops continuously
 • Can use a trigger list to control operation (sensitivity list)
   • @(a,b,c)
   • In absence of a trigger list, it will re-evaluate when the last <LHS> assignment completes


 module clock_gen (output reg clock);

   initial
     clock = 1’b0;       // must initialize in initial block

   always                // no trigger list for this always
     #10 clock = ~clock; // always will re-evaluate when
                         // last <LHS> assignment completes
 endmodule
Sensitivity Lists
• Conditionally evaluate inside of always block
  • Any change on sensitivity list triggers block
        always @(a,b,c) begin
          ...
        end

• Original way to specify trigger list: always @(a or b or c)
• In Verilog 2001 can use , instead of or: always @(a, b, c)
• Verilog 2001 also has * for combinational only: always @(*)
  • Anything on the RHS of assignments are included in the list
        always @(*)
          if (a==b) c = d ^ e;        Sensitivity list is @(a,b,d, e)
          else c = d;
always_comb
• System Verilog introduced always_comb
 • Does not have a sensitivity list
 • More descriptive than always@(*)
 • Simulator will warn if you did not infer combinational logic with it

Flip Flop Inference
• Output of flip flops change at the rising (or falling) edge of clock
• Described using always block
• In sensitivity list, specify edge-sensitive to clock (vs level-sensitive)
  • Block evaluated when there is an edge (vs when signal value changes)
  • Use keywords posedge and negedge
• A posedge is on the transitions
  • 0 → x, z, 1                                   reg q;
                                                                           d         q
  • x, z →1
                                                  always @(posedge clk)
• A negedge is on the transitions                   q <= d;                    clk

  • 1 → x, z, 0
  • x, z → 0

Flip Flop Inference in System Verilog
• System Verilog introduced always_ff
 • Tells the tool you intend to infer a flip flop
 • Will get warning if it did not infer a flop
