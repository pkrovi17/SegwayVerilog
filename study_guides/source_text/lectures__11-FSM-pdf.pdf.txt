Coding FSM
• What is the best way to code FSM?
  • Best to separate combinational (blocking) from
    sequential (non-blocking)
    → Combinational logic here is more complex and not
    guaranteed to evaluate in 1 sim cycle

  • Output logic and state transition logic can be coded in
    the same always block since they have the same inputs

  • Output logic and state transition logic are ideally suited
    for a case statement

FSM Coding Guidelines
1. Keep state assignment in separate always_ff block using non-blocking “<=“
   assignment
2. Code state transition logic and output logic together in an always_comb block
   using blocking assignments
3. Assign default values to all outputs, and the nxt_state registers. This helps avoid
   unintended latches
4. Remember to have a default to the case statement.
  • Default should be (if possible) a state that transitions to the same state as reset would take the
    SM to.
  • Avoids latches
  • Makes design more robust to spurious electrical/cosmic events.
