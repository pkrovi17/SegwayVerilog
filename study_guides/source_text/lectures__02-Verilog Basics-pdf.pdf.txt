Verilog Basics – Ports
• Port directions
  • input
  • output
  • inout (bidirectional)

• Port size
  • Scalar (single bit) – default when no size is specified
    • input cin;

  • Vector (multiple bit) – specify size using [<range>] (before signal)
    • output [7:0] out;     // Convention is MSB to LSB (left to right)
    • input [0:4] in;       // Legal syntax
    • inout [3:2] data;     // Range can be between any 2 numbers, don’t have to include 0

Verilog Basics – Signal Types
• Signal is physically voltage on a wire
• Main synthesizable Verilog types:
  • wire – for signals driven by purely combinational logic
    • Needs a driver (e.g., primitive gate, module, I/O)
  • reg – for inferring logic in procedural (always) block
    • Retain value until a new one is assigned
    • Can be changed in simulation by assigning a new value

Verilog Basics – Numbers
• General format is: <size>’<base><number>
• Specify size based on smallest needed in the design
  • If not specified, default size depends on simulator/machine
• Available bases:
  • d – decimal (default)                                Examples:
  • h – hexadecimal (used very often)
                                                         4’b1101 //4-bit binary number equal to 13
  • b – binary (used often for smaller numbers)          10’h2E7 //10-bit # in hex equal to 2E7 (743)
  • o – octal                                            10’hFE7 //10-bit # in hex equal to 3E7 instead of FE7
• Number can have x or z characters as values            12’h13x //12-bit hex # with lower 4 bits unknown
  • x = unknown                                          -16’h3A //16-bit # with -3A in hex (FFC6 in 2’s comp)
  • z = high impedance
• Supports negative numbers as well

Module Coding Styles
• Modules can be specified in different ways
  • Structural – connect primitives and modules
  • Dataflow – use continuous assignments
  • Behavioral – use initial and always blocks


• A single module can use more than one method
Structural Verilog
• A schematic in text form (i.e., a netlist)
• Build up a circuit from gates and modules
  • Gates are primitives (part of the language)
  • Modules are user-defined
• Build up hierarchy from smaller pieces when we design
  • Architecture: typically top-down
  • Design & verification: typically bottom up

Port Connections
• Positional / connect by order
  • Ok for designs with very few ports & interchangeable input ports (e.g., and/or/xor)
• Explicit / connect by name
  • Helps avoid connection errors, no need to remember port order, easier to read
  • .<port name>(<signal name>)
• Empty port connections
  • Input: high impedance
  • Output: not used
Example: module full_add(A,B,Ci,S,Co);
full_add iadd(.A(X),.B(Y),.S(Z),.Co(ov));    //Ci is high impedance
full_add iadd(.A(X),.B(Y),.Ci(1’b0).S(Z), ); //Output Co unused

full_add iadd(.A(X),.B(Y),.Ci(1’b0).S(Z), .Co()); //Better code

• Can instantiate modules as a vector                           B[7] A[7]   B[6] A[6] …     B[1] A[1]   B[0] A[0]



module RCA8 (                                          Cout     full_add    full_add   …    full_add    full_add    Cin
   input [7:0] A,B,        // two 8-bit vectors to be added
   input        Cin,       // An optional carry in bit
   output [7:0] S,         // 8-bit sum
                                                                     S[7]     S[6]     …       S[1]       S[0]
   output       Cout       // carry out
);

  // Co of lesser significant bit form Cin of more significant bit
  logic [7:0] Carries;

  // Implement Full Adder as structural Verilog
  full_add add0(.A(A[0]), .B(B[0]), .Cin(Cin),        .S(S[0]), .Cout(Carries[0]));
  full_add add1(.A(A[1]), .B(B[1]), .Cin(Carries[0]), .S(S[1]), .Cout(Carries[1]));
  full_add add2(.A(A[2]), .B(B[2]), .Cin(Carries[1]), .S(S[2]), .Cout(Carries[2]));
  full_add add3(.A(A[3]), .B(B[3]), .Cin(Carries[2]), .S(S[3]), .Cout(Carries[3]));
  ...
  full_add add7(.A(A[7]), .B(B[7]), .Cin(Carries[6]), .S(S[7]), .Cout(Carries[7]));

  buf iBF(Cout, Carries[7]);

endmodule

Why Know Structural Verilog?
• DUT code will mostly be dataflow or behavioral
• Testbenches primarily in behavioral

• What needs structural Verilog?
  • Building hierarchy (instantiating blocks to form higher level functional blocks)
  • Synthesis tools output structural Verilog (gate-level netlist)
    → you need to be able to read this output
