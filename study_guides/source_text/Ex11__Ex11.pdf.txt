    Universal Asynchronous Receiver / Transmitter (UART)
    • For asynchronous serial communication
    • The transmitter (TX) and receiver (RX) have an agreed upon Baud rate and
       frame format
        • Standard Baud rates: 4800, 9600, 19200, 38400, 57600, 115200, 230400, 460800, 921600
        • Frame formats: 1 start bit         5-9 data bits       0 or 1 parity bit 1 or 2 stop bit

    • Transmitter sits idle (high) until told to transmit.

    • We will use what’s commonly referred to as the 8N1 format
           •   8 data bits, no parity bit, 1 stop bit

    UART TX Design
    Suggested process:
    • Think about what kind of things need to be done
      → what datapath elements can do that for you?
    • Then think about when these things need to be done
      → how should the FSM control signals going to the data path?

    For example:
    • Bits are transmitted 1 bit at a time → Need registers to hold data to be
        transmitted
    •   When Baud period is up, transmit next bit → Need counter for Baud rate
    •   Once all bits are transmitted, assert tx_done → Need counter to keep track of
        how many bits have transmitted

    • Are there different “phases” that the circuit need to work in?
        •   Yes. Need to wait for input, and we don’t do anything in this phase. Then need to
            transmit. So we will need to have an FSM.
        •   Figure out the datapath elements first before looking at when to change the control

    There are a few possible designs:
    A. Can have a register load in the frame (all 10
       bits) and use a MUX to select which bit to
       output onto TX
    B. Can have a shift register to load in the          B
       frame (all 10 bits) and shift right every time.
       TX is just the value at bit 0.
    C. Shift register like B, but can save 1 register
       for the stop bit and just tie a static 1’b1
       (since line is high during idle)
